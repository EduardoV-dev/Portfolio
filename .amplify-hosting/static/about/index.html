PROFESSIONAL BACKGROUND

How I Got Here

I started in frontend development and grew into full-stack engineering, driven by a need to own the entire product, from the interface users interact with down to the backend services and cloud infrastructure that powers it. That path led me to stop working in isolation and start bridging engineering, product, and marketing teams.

Over 4+ years, I've built and shipped end-to-end marketing web experiences in React, Next.js, and Svelte, backed by Node.js and Express APIs on AWS. I've led full-stack feature implementations, improved site speed and accessibility, and partnered with DevOps on deployment workflows that keep releases reliable and performance stable.

I gravitate toward roles where technical decisions have direct business impact, where improving a page's performance translates to better conversions, or a cleaner architecture lets a team ship faster. The work I'm proudest of consistently delivers on both fronts.

HOW I WORK

Engineering Philosophy

The principles I return to when making technical decisions under real product pressure.

  • Product Thinking

    Good engineering decisions start with understanding the product problem. I think in user outcomes first, then work backward to the technical solution.

  • Full Ownership

    I'm most effective when I own a surface end-to-end, from the first interface to deployment. Ownership drives better decisions and faster iteration.

  • Scale by Design

    I don't over-engineer for scale that doesn't exist yet, but I design seams that let systems grow. Premature optimization is a trap. Ignoring constraints is worse.

  • Clarity Over Cleverness

    Code is read far more often than it's written. I favor explicit, straightforward solutions that any engineer can reason about over abstractions that only I can maintain.
